# Data-processing inventory (source audit) — 2026-10-12

**Purpose:** the factual basis for the privacy policy and for the App Store "App Privacy" answers.
Every row cites the code it comes from. Produced for AS-POLICY (`docs/agent-coordination.md`) by a
read-only audit of `main` at `bf4a16a` (the Apple-revocation queue, Ask guidance and comments RLS
fix were re-read at that commit). It describes **source, not production**: secrets, flag values,
cron on/off state, live Storage/RLS policies, provider contracts, log retention and backups are not
in the repo (§G). The audit worktree's shell was blocked part of the time, so repo-wide greps ran
but one analytics-name grep over `ios/` and `extension/` did not (those were read by hand).

Citation prefixes: `F` = `supabase/functions`, `M` = `supabase/migrations` (14-digit timestamp;
legend at the end), `S` = `src`, `R` = repo root. Tags: [user] explicit user action, [auto]
automatic after a save, [cron] scheduled, [opt] flag/ops-gated or optional, [anon] unauthenticated.

## Top findings for the policy rewrite

1. **Files are not private.** Bucket `stash-media` is `public = true` with a SELECT policy for everyone (M/20250622205827:55-56; M/20250927024744:2-3); the web uploads original bytes (EXIF GPS kept: S/utils/localFileAnalysis.ts:83-96, S/utils/fileUploader.ts:50-62); web item delete leaves the files behind (S/utils/itemOperations.ts:136-183). The old policy said "Everything you save is private by default".
2. **Share links and the public-feed API return notes, page text, summary and the whole `attributes` blob** — exact coordinates when the location pin was on (M/20261009123000:14-48; F/get-public-feed/index.ts:39-68).
3. **~25 processors vs 5 listed.** Beyond Supabase/OpenAI/Stripe/Twilio/Firecrawl the deployed code calls Vercel, Resend, Mapbox, Jina Reader, the Internet Archive, SearchApi, TranscriptFetch, allorigins.win, BigDataCloud, Google, Apple, Microsoft's Office viewer, embed hosts and (flag-gated) a Fly.io worker. OpenAI use spans embeddings, vision/OCR, PDF upload, audio, structured extraction and QA sampling.
4. **Location** is captured (web pin, iOS pin) and stored unrounded; photos containing a street address are geocoded automatically (Mapbox) with no setting (F/_shared/placeEnrichment.ts:155-193; F/add-file/index.ts:136-146).
5. **Flag-gated QA pipelines** sample real users' saved links (title, description, summary, first 6,000 chars of page text, preview image) for a hosted worker and OpenAI (F/quality-model/index.ts:33-45; F/quality-dispatch/handler.ts:13-47). Default off; production state unknown.
6. **Admin dashboard** lets an `admin_users` account read any member's email, sign-in stats and full library (F/admin-stats/index.ts:127-165; M/20260908120000:39-116). Reads are console-logged only.
7. **Deletion:** account delete keeps the Stripe customer record (F/delete-account/index.ts:9-11); an Apple revoke Apple does not confirm survives the account in `apple_revocations` (token kept only while pending; retried up to 20 times, only for accounts confirmed gone; settled rows purged after 30 days; exhausted rows retained for an operator — F/_shared/appleRevocation.ts). Logs, backups and provider copies are outside the code. Item delete does not remove storage files, `card_feedback` snapshots or `chat_feedback`.
8. **Only explicit retention in code:** 35 days (hosted QA tables), 2 days (homepage-demo IP hashes), the revocation queue above. Everything else lives until the user deletes it.
9. **Phone:** the web sign-up/Settings phone UI was withdrawn 2026-10-12; `twilio-webhook`, `user_phone_numbers` and the iOS `PhoneSection` (Codex's) remain; numbers connected earlier stay linked.
10. **Published dates:** privacy "september 7, 2026"; terms "august 9, 2026"; there was no `/support` page.

## B. Storage and retention

**B1. Stores of user content** (account delete removes all of these by FK cascade from `auth.users` unless noted): `items` (content, supplemental_note, description, summary, page_body, title, url, file_path, attributes = location/place/link/media/enrichment/object facts/note_images, is_public, comments_enabled, share_token, reminders, pinned_at, fts); `embeddings`, `item_tags`, `comments`, `enrichment_*`, `object_intelligence_jobs` cascade from items; Storage `stash-media` (public; `<uid>/…`, previews, maps, document previews, staging, WhatsApp media); `user_profiles` (username, display_name, first/last name, bio, avatar_url, public_feed_enabled, handle_confirmed); `user_follows`; `user_phone_numbers`, `sms_conversations`, `pending_intents`; `apple_sign_in_tokens` (cascade); `apple_revocations` (**no FK**: survives the account, token only while pending); Ask: `conversations`, `messages`, `chat_feedback`, `retrieval_log`; `card_feedback` (snapshot of title/description/url/file_path; item_id SET NULL on item delete), `user_preferences`, `tags`, `agent_grants`, `agent_access_log`, `subscription_status_cache`, `capture_receipts`, `admin_users`, `enrichment_quality/jobs/attempts/revisions` (revisions keep before/after title, description, summary, page_body, attributes), `enrichment_eval_cases`; QA copies `hosted_quality_*`, `hosted_visual_*` (purged by BEFORE DELETE triggers on items). Auth schema: email, identities, sessions, `auth.audit_log_entries` (never deleted by the repo).

**B2. `delete-account`** (F/delete-account/index.ts): 1 Stripe subscriptions canceled, customer kept and tagged; 2 every object under `stash-media/<uid>/` removed; 3 Apple tokens staged in `apple_revocations` (unreadable → 503, nothing deleted); 4 `auth.admin.deleteUser` cascades; 5 Apple revocation after the account is gone, retried by `apple-revocation-sweep` only for accounts confirmed absent (≤20 attempts; exhausted rows retained for an operator; revoked/invalid purged after 30 days). Not deleted / not covered: the Stripe customer and invoices; `auth.audit_log_entries`; Supabase function logs (which carry emails, URLs, OCR/vision text, PDF text, tag prompts, phone numbers, SMS bodies); backups/PITR; copies at providers; Internet Archive snapshots; crawler caches of share cards.

**B3. Item delete (web)** (S/utils/itemOperations.ts:136-183) deletes embeddings and the `items` row; FKs remove derived tables; **no call removes the item's storage objects** (upload, preview, map, document preview), which stay readable at their public URLs until account deletion. Other clients' delete paths were not checked.

**B4. Scheduled / continuing processing** (pg_cron): `reminder-digest` 13:00 UTC (Resend); `transcribe-audio-sweep` every 10 min; `enrichment-maintenance` hourly (assessment of every item; repairs only if ENRICHMENT_REPAIR_ENABLED); `object-intelligence-worker` every 5 min [opt]; `hosted-quality-dispatch` every 5 min [opt]; `hosted-visual-monitor` (created inactive) [opt]; `apple-revocation-sweep` every 15 min. Always-on triggers: enrichment assessment on every items change, object-intelligence enqueue, media settle. Post-response background work follows every add-note/add-url/add-file. Webhooks: Stripe, Twilio.

**B5. Explicit retention found in code:** hosted QA tables 35 days; canary media orphans 24 h; `homepage_enrich_hits` 2 days; `apple_revocations` as above. None for items, embeddings, messages, retrieval_log, agent_access_log, enrichment_* (incl. revisions), chat_feedback, card_feedback, capture_receipts, sms_conversations, apple_sign_in_tokens, share tokens (no expiry), storage files.

## C. Location

Web pin: opt-in per post, default off; browser sends coordinates to BigDataCloud; stored unrounded in `items.attributes.location` {label, latitude, longitude, accuracy_m, city, region, country, source, captured_at} (S/hooks/useCaptureLocation.ts; S/types/itemAttributes.ts:18-35). iOS pin: opt-in per account + When-In-Use permission; CLGeocoder; stores coordinates as returned with accuracy_m; manifest declares CoarseLocation (R/ios/Stash/PrivacyInfo.xcprivacy:95-109); the Share extension never prompts. Derived place (automatic, no setting): map links, listing pages and photos whose text holds a street address → `attributes.place` + a Mapbox map PNG in the public bucket. EXIF: the web reads only DateTimeOriginal/Model locally but uploads the original bytes (GPS kept); iOS strips GPS and metadata before upload. `attributes.location` shows on cards ("posted from"), is returned whole by the public feed and share RPC, label-only over MCP, not embedded.

## D. Public exposure

Public feed (`/feed/:username`, `get-public-feed`, verify_jwt=false): profile + every `is_public` item with `select('*')` minus reminder columns — content, supplemental_note, page_body, summary, attributes (coordinates), share_token, file_path. `get-discover-feed`: every user's public items. RLS "Anyone can view public items". Share pages: `shared_item(token)` returns title, description, url, file_path, summary, page_body, content, attributes, dates, username, display_name; token is the only credential (10 chars, client-minted, no expiry, owner can clear). Profiles: `user_profiles` SELECT for everyone (username, display_name, first/last name, bio, avatar_url, created_at); provider full name becomes display_name. Follows: world-readable. Comments: readable on public items; direct inserts now require the signed-in author (M/20261012220000); `post-comment` still accepts anonymous posts via the service role. Storage: public bucket, every object fetchable by URL regardless of item privacy. Operator: admin-stats returns every account's email, username, display_name, login counts, item counts and any member's whole library.

## E. Client-side data

Web: supabase-js session in localStorage; `stash_recent_searches` (last 5 queries); `editDraft-<itemId>` (title, description, notes, sticky note; dropped after 24 h on reopen); dismissed-hint, banner, spot, loading-line and pinned-mole flags. Nothing clears these on sign-out or account delete. The only cookie write is shadcn's `sidebar:state`, never mounted. Analytics / error-reporting SDKs: none found (src, public/site, index.html, package.json, extension, iOS manifest: NSPrivacyTracking=false). Browser third-party requests: Google Fonts; Google GIS + Apple JS on /auth; BigDataCloud (pin); noembed/YouTube oEmbed on paste; Microsoft viewer; embed iframes; remote images via `image-proxy` (logs each URL, 1-day cache). Chrome extension: contextMenus, storage, scripting, host access http(s)://*/*; explicit gestures only; session in chrome.storage.local; no analytics. MCP: Supabase OAuth 2.1 consent per app; read-only tools; every call logged and visible in Settings. iOS SDKs (main): supabase-swift + swift-* support packages; candidate 11+ adds GoogleSignIn 10.0.0 with AppAuth, GTMAppAuth, GoogleUtilities, GTMSessionFetcher, app-check, promises (Codex's branch).

## F. Previous policy text vs code (what the 2026-10-12 draft corrects)

1. "email … and a phone number if you choose to connect WhatsApp or SMS" — also provider name/picture, username/handle, first/last name, Apple refresh token; phone can no longer be connected.
2. "links, notes, images, documents, voice recordings … titles, descriptions, searchable text" — omits video, transcripts, OCR, embeddings, coordinates/places, reminders, tags, Ask conversations, feedback.
3. "subscription status and error logs" — logs carry content-derived text; retrieval_log, agent_access_log, enrichment revisions, admin sign-in stats.
4. "one purpose: making your own stash useful" — QA sampling, admin access, user-chosen public/share/MCP exposure.
5. "private by default … publicly only if you explicitly mark an item as public" — rows yes; files in a public bucket; share links; world-readable profiles.
6. Provider list of five — see A.
7. "We do not sell … ads … train AI models" — no such code; third-party training cannot be verified from source (the draft keeps it as Stash's own conduct and says OpenAI is used through its API).
8. "Deleting an item removes it and its derived data" — storage files, card_feedback, chat_feedback stay.
9. "Deletion is immediate and permanent …" — Stripe customer kept; Apple revocation token may outlive the account until Apple confirms; audit log, function logs, backups, provider copies.
10. Not addressed before: location, share links, MCP, feed scope, retention, backups, local storage, children, how changes are announced.

Terms (public/terms): silent on share links, MCP, QA sampling, comments, other users' content, reporting — see `docs/superpowers/specs/2026-10-12-public-feed-moderation-design.md` §5.
